# 桌面尺寸、主页信息与荣誉列表实施计划

## 目标

依据已批准的设计规格，完成桌面端均衡放大、主页主修课程、两个早期研究详情入口、Academic research 页面锚点和 9 项荣誉列表，并验证桌面、手机和打印布局。

设计依据：

- `docs/superpowers/specs/2026-08-31-desktop-scale-profile-details-honors-design.md`

## 实施步骤

### 1. 建立修改前基线

涉及文件：

- `styles.css`
- `index.html`
- `projects/academic-research.html`
- `resume.html`

检查内容：

1. 确认工作区没有未提交的网站改动。
2. 记录当前桌面端主要尺寸和响应式断点。
3. 确认现有内部链接、HTML 标识符和脚本语法均正常。

### 2. 调整桌面尺寸和响应式断点

修改 `styles.css`：

1. 将桌面侧栏宽度改为 `292px`。
2. 将正文宽度改为 `min(940px, calc(100% - 88px))`。
3. 将基础字号改为 `16px`。
4. 按规格同步调整侧栏姓名、英文名、资料、导航及正文标题、导语、项目正文、日期和辅助标签字号。
5. 将移动布局切换点改为 `960px`。
6. 检查固定宽度、日期列和内容间距是否需要同步微调。

验证：

- CSS 语法无明显错误。
- 现有移动端规则仍覆盖桌面规则。

### 3. 增加主页主修课程和研究详情入口

修改 `index.html`：

1. 在 `research-lines` 中增加“主修课程”第三栏。
2. 使用已确认的 12 门课程及固定顺序。
3. 给智能会议项目添加指向 `#meeting-system` 的详情链接。
4. 给 Banach 项目添加指向 `#banach-fixed-point` 的详情链接。

修改 `styles.css`：

1. 将 `research-lines` 调整为 `0.95fr 1fr 1.5fr`。
2. 在 `960px` 以下改为单栏。
3. 确保课程名称可自然换行且不产生横向溢出。

### 4. 扩展两个早期研究项目

修改 `projects/academic-research.html`：

1. 为智能会议项目设置 `id="meeting-system"`。
2. 为 Banach 项目设置 `id="banach-fixed-point"`。
3. 将两个项目各扩展为独立内容单元。
4. 只使用规格中确认的项目内容，不新增指标、发表状态或仓库链接。
5. 确保锚点具有足够的 `scroll-margin-top`。

验证：

- 两个目标 `id` 唯一。
- 从主页链接跳转后对应项目标题可见。

### 5. 重构主页和 CV 荣誉列表

修改 `index.html` 与 `resume.html`：

1. 标题统一为 `Honors and awards`。
2. 按规格写入相同的 9 项奖项。
3. 每项使用独立条目，年份与完整名称分开标记。
4. 保持两个页面的文字和顺序一致。

修改 `styles.css`：

1. 移除荣誉列表的两列 `columns` 布局。
2. 新增“年份列 + 名称列”的文档式条目。
3. 长奖项名称允许自然换行。
4. 移动端改为年份在上、名称在下。
5. 打印样式保持单栏并避免条目跨页断裂。

### 6. 静态检查

执行：

1. `git diff --check`。
2. `node --check script.js`。
3. 检查重复 `id`。
4. 检查所有站内链接目标。
5. 检查主页和 CV 的奖项文字、年份与顺序一致。
6. 检查 12 门课程全部出现且没有重复。
7. 检查旧的两列荣誉写法和合并奖项已移除。

### 7. 浏览器验收

使用本地服务器和真实浏览器检查：

- `1366 × 768`
- `1440 × 900`
- `1920 × 1080`
- `390 × 844`

逐页检查：

- `/`
- `/projects/academic-research.html`
- `/resume.html`

验收内容：

1. 页面没有横向滚动。
2. 桌面 100% 缩放下侧栏和正文大小合适。
3. 三栏简介和移动端单栏均正常。
4. 两个新增详情链接跳转正确。
5. 9 项荣誉完整可读。
6. 浏览器控制台无新增错误。
7. 打印样式中的 CV 荣誉条目不重叠、不截断。

完成测试后恢复浏览器默认视口。

### 8. 提交、推送和发布验证

1. 查看最终差异，确认只包含计划内文件。
2. 提交网站修改。
3. 推送到 `origin/main`。
4. 确认 GitHub Pages 部署成功。
5. 通过自定义域名检查新版主页包含主修课程和 2026 年新增奖项。

## 完成标准

- 已批准规格中的所有内容均已实现。
- 四种视口通过验收。
- 主页、Academic research 和 CV 内容一致、链接有效。
- Git 工作区干净。
- GitHub Pages 部署成功并可从自定义域名访问。
